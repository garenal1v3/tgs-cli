# Проект tgs (searchtgcli)

CLI-клиент для поиска по Telegram через пользовательский аккаунт (MTProto).
Основной use case — инструмент для AI-агентов (Claude Code, Codex, OpenCode и др.), но удобен и для людей.

- **Язык**: Go
- **Telegram-библиотека**: gotd/td (чистый Go MTProto, без CGO)
- **CLI-фреймворк**: Cobra
- **Лицензия**: GPL-3.0
- **Бинарник**: `tgs`
- **Вывод**: JSON по умолчанию
- **Профили**: мульти-аккаунт через --profile (аналог AWS CLI)
- **Авторизация**: импорт сессии из Telegram Desktop + override через env (TGS_API_ID, TGS_API_HASH)
- **Дистрибуция**: Homebrew, GitHub Releases, go install, Docker, snap/AUR

## Проверки перед пушем (pre-push hook)

В репозитории зашит **pre-push git hook** (`.githooks/pre-push`, включается через `git config core.hooksPath=.githooks`). При `git push` он автоматически прогоняет в Docker полный CI-набор и блокирует push при любой ошибке:

1. сборка CI-образа `tgs-ci:local` из `Dockerfile.ci`;
2. `golangci-lint run ./...` (линт);
3. `make test` (тесты);
4. `cd docs && hugo --minify` (сборка документации).

Линтеры, тесты и сборку docs **НЕ нужно прогонять отдельно перед пушем** — хук всё проверит сам. Просто коммить и пуш; если push упал на хуке — читай его вывод и чини. Ручной прогон осмыслен только в быстром цикле во время работы, не как обязательный шаг перед каждым push.

## Документация и README

После ЛЮБОЙ работы проверяй, нужно ли обновить документацию или README.
Если да — обновляй СРАЗУ на ВСЕХ трёх языках (en, ru, zh). Без исключений.

### Языки
- English — основной язык, всегда актуален
- Русский (README_ru.md, docs/content/ru/) — перевод, может отставать
- 中文 (README_zh.md, docs/content/zh/) — перевод, может отставать
- В неанглийских версиях README добавлять дисклеймер о возможном отставании от английской версии

### Стиль README (по образцу tdl)
- README — это лендинг, а не документация. Минимум текста, максимум ссылок на docs-сайт
- Лого + tagline + переключатель языков в шапке
- Бейджи: flat-square стиль (Go version, license, CI, release, downloads)
- Фичи: короткие bullet-points, одна строка на фичу. Тон неформальный, живой, без канцелярита
- НЕ включать в README: инструкции по установке, примеры команд, конфигурацию, troubleshooting — всё это в docs-сайте
- Секции: features, preview (позже), documentation link, contributors, license
- Тон: дружелюбный, уверенный, лаконичный. Допустимы шутки и personality

### Стиль документации (Hugo-сайт)
- Структура: getting-started/, guide/, reference/
- Технический, но доступный язык
- Примеры команд обязательны в каждом разделе guide/
- Каждая страница — один концепт, не мешать темы
